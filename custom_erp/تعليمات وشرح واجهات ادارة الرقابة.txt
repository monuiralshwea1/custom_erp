1) نظرة عامة
================================================================================
نظام "مراقبة وتتبع نشاط المستخدمين" يجمع سلوك المستخدمين داخل النظام في سجل
واحد موحّد قابل للمراجعة والبحث، ويعتمد على Frappe/ERPNext نفسه كلما كان
ذلك ممكناً (سجل المسارات Route History، سجل النشاط Activity Log، سجل الوصول
Access Log، سجل المشاهدة View Log، سجل الإصدارات Version).

مبدأ التصميم: "لا نُكرر ولا نُخترع"
  - كل حدث مسجَّل يجب أن يكون له دليل فعلي (سجل في قاعدة البيانات أو مستند).
  - الأحداث التي يسجّلها Frappe أصلاً (تسجيل الدخول/الخروج/محاولات الفشل) تُقرأ
    من سجل Frappe الأصلي ولا تُنسخ في سجلنا، مع منع التكرار على مستوى SQL.
  - سجلنا الموحّد (User Activity Audit Log) يضيف ما لا يغطيه Frappe:
    اسم المستخدم + عنوان IP + المتصفح + نوع النشاط + الحقول المتغيّرة + معرّف
    ارتباط + وصف موجز.

مهمّة تحذير: هذه المؤشرات إحصاءات نشاط فحسب، وليست دليلاً على إساءة
الاستخدام. يجب مراجعة السياق المحيط قبل استخلاص أي نتيجة.

2) الواجهة 1: تقرير نشاط المستخدمين (User Activity Audit Report)
================================================================================
المسار        : /app/query-report/User Activity Audit Report
نوعه         : Script Report (تقرير سكربت قياسي داخل custom_erp)
الوصول       : قائمة التقارير ← Custom App، أو من بطاقة "الرقابة والامتثال"
                في مساحة العمل الرئيسية، أو مباشرة بالرابط أعلاه.
الصلاحيات    : System Manager + Audit Manager فقط.

أ) الفلاتر المتاحة
   ------------------------------------------------------------------
   From Date          من تاريخ        - بداية نطاق البحث (افتراضياً آخر 7 أيام)
   To Date            إلى تاريخ       - نهاية نطاق البحث (افتراضياً اليوم)
   User               المستخدم        - مستخدم واحد محدّد
   Activity Type      نوع النشاط      - Login / Logout / Failed Login / Impersonate
                                        / Route Visit / Document View /
                                        Document Create / Document Update /
                                        Document Delete / Document Submit /
                                        Document Cancel / Document Amend /
                                        Document Print / Report Export /
                                        File Download / Access Denied / Error / Other
   Document Type      نوع المستند     - restricts to a specific DocType
   Document           المستند         - restricts to a specific document
                                        (قائمة ديناميكية حسب نوع المستند)
   Page Route         مسار الصفحة     - جزء من مسار الواجهة (بحث جزئي)
   Outcome            النتيجة         - Success / Failure / Denied / N/A
   IP Address         عنوان IP        - عنوان محدّد
   Event Source       مصدر الحدث      - Custom App / Frappe / الكل
   Rows per Page      عدد الصفوف      - 100 (الافتراضي، قابل للزيادة)
   Page               الصفحة          - رقم الصفحة (للتصفّح)

ب) الأعمدة المعروضة
   ------------------------------------------------------------------
   التاريخ والوقت | المستخدم | نوع النشاط | نوع المستند | المستند |
   مسار الصفحة | الوصف | النتيجة | عنوان IP | مصدر الحدث |
   المستخدم المحاول تسجيل دخوله | الحقول المتغيّرة

   - عمود "المستند" رابط قابل للنقر: يفتح المستند الأصلي مباشرةً (يتحقق Frappe
     من الصلاحية عند الفتح).
   - عمود "الحقول المتغيّرة" يعرض أسماء الحقول فقط (بلا أي قيم).

ج) بطاقات الملخص الإداري (أعلى التقرير)
   ------------------------------------------------------------------
   إجمالي الأحداث | المستخدمون النشطون | زيارات الصفحات |
   إنشاء / تعديل / حذف | محاولات دخول فاشلة | طباعات / صادرات | صلاحيات مرفوضة

د) الرسم البياني
   توزيع الأحداث حسب نوع النشاط (أعمدة).

هـ) الترقيم على الخادم
   - الترقيم يتم داخل قاعدة البيانات (LIMIT/OFFSET) وليس في المتصفح؛ فلا يتم
     تحميل آلاف السجلات دفعة واحدة.
   - أزرار "الصفحة السابقة" / "الصفحة التالية" في أعلى التقرير.
   - زمن التنفيذ الفعلي المقاس: ≈ 0.06 ثانية لمصفحة من 50 صفاً.

و) زر "إعدادات الرقابة"
   ينقلك مباشرةً إلى واجهة الإعدادات.

3) الواجهة 2: سجل نشاط المستخدمين (User Activity Audit Log)
================================================================================
المسار        : /app/user-activity-audit-log
نوعه         : سجل قياسي (DocType) للقراءة فقط
الصلاحيات    : Audit Manager (قراءة/تصدير فقط) + System Manager (كامل)

الحقول
   ------------------------------------------------------------------
   المستخدم | التاريخ والوقت | نوع النشاط | النتيجة | نوع المستند | المستند |
   مسار الصفحة | الوصف | الحقول المتغيّرة | عنوان IP | متصفح/جهاز المستخدم |
   طريقة الطلب | طريقة الواجهة البرمجية | مصدر الحدث | معرّف الارتباط |
   المستخدم المحاول تسجيل دخوله

الاستخدامات النموذجية
   - البحث والتصفية السريعة بالفلاتر القياسية (Filter By).
   - التصدير إلى Excel/CSV (متاح لدور Audit Manager).
   - مراجعة حقل "معرّف الارتباط" لربط الأحداث المتسلسلة (correlation_id).

قواعد الحماية المطبّقة على السجل
   - لا توجد صلاحية "إنشاء" أو "تعديل" لأي دور عادي.
   - الخادم هو من يحدّد "المستخدم" من الجلسة الموثّقة، فلا يمكن تزويره.
   - الحذف ممنوع إلا بـAdministrator، وكل عملية حذف تُسجَّل هي نفسها.

4) الواجهة 3: إعدادات مراقبة نشاط المستخدمين (User Activity Audit Settings)
================================================================================
المسار        : /app/user-activity-audit-settings
نوعه         : إعدادات (Single DocType)
الصلاحيات    : System Manager (تعديل) + Audit Manager (قراءة)

الحقول
   ------------------------------------------------------------------
   [عام]
   - تفعيل مراقبة نشاط المستخدمين        : تشغيل/إيقاف التسجيل بالكامل
   - مدة الاحتفاظ بالسجلات (أيام)        : 0 = لا حذف تلقائي إطلاقاً
   - أقصى عدد صفوف في الصفحة              : حد أعلى مقيّد لالتقاط REPORT

   [التقاط الأحداث]
   - تسجيل أحداث المستندات               : إنشاء/تعديل/حذف/اعتماد/إلغاء
   - تسجيل أحداث الدخول والخروج
   - تسجيل الطباعة والتصدير والتنزيل والأخطاء
   - تسجيل زيارات الصفحات

   [مصادر Frappe الأصلية المدمجة في التقرير]
   - تضمين سجل المسارات الأصلي (Route History)
   - تضمين سجل الوصول الأصلي (Access Log)
   - تضمين سجل المشاهدة الأصلي (View Log)
   - تضمين سجل إصدارات المستندات (Version)  (مطفأ افتراضياً)

   [الاستثناءات]
   - نافذة منع تكرار تسجيل المسار (ثانية) : افتراضياً 60 ثانية
   - أنواع المستندات المستثناة من التسجيل
   - الحقول المستثناة من التسجيل
   - أنماط الحقول الحسّاسة                 : قائمة مفصولة بفواصل

مثال على أنماط الحقول الحسّاسة (افتراضية):
   password, passwd, pwd, secret, token, api_key, api_secret, private_key,
   signature, otp, credential

8) قواعد منع التكرار ومعالجة التكرار بين المصادر
================================================================================
أ) منع التكرار المتكرر (داخل سجلنا):
   - زيارات الواجهة: يُسجَّل المسار مرة واحدة فقط خلال نافذة "نافذة منع تكرار
     تسجيل المسار" (افتراضياً 60 ثانية) لنفس المستخدم.
     الاختبار: 3 طلبات متتالية بنفس المسار ← سجل واحد فقط.
   - المستند: عند الإنشاء يُستدعى after_insert ثم on_update معاً؛ يتم تجاهل
     on_update عند الإنشاء (in_insert) حتى لا يُسجَّل الحدث مرتين.

ب) منع التكرار بين المصادر (سجلنا مقابل سجل Frappe):
   - يتم على مستوى SQL: يُسقَط أي حدث من مصدر Frappe إذا وُجد حدث مكافئ في
     سجلنا (نفس النوع + نفس المستخدم الفعّال + نفس المستند + خلال 120 ثانية).
   - مثال: تسجيل الدخول يظهر مرة واحدة فقط (من سجل Frappe) لا مرتين.

9) الحقول الحسّاسة واستثناءات التسجيل
================================================================================
1) لا تُسجَّل أي قيم حقول إطلاقاً — فقط أسماء الحقول المتغيّرة.
2) الحقول المطابقة لأنماط "الحقول الحسّاسة" لا يُسجَّل حتى اسمها.
3) قائمة استثناءات الحقول لكل نوع مستند (واجهة الإعدادات).
4) قائمة استثناءات أنواع المستندات بالكامل (واجهة الإعدادات).
5) لم تُسجَّل كلمة مرور أو رمز جلسة أو مفتاح API أو أي سر.
6) محاولات الدخول الفاشلة تُسجَّل باسم "المستخدم المحاول" (Guest) ولا تُنسب
   لمستخدم مُصادَق عليه.

10) الأداء واستهلاك قاعدة البيانات وسياسة الاحتفاظ
================================================================================
- الكتابة: سجل واحد لكل حدث، عبر إدراج مباشر في قاعدة البيانات.
- الحقول المستثناة من التسجيل: 12 مستند نظام (Version, Activity Log, ...)
  حتى لا يتضخّم السجل ولا يحدث تسجيل متكرر.
- منطق الأعمال (company_isolation) لم يُعدَّل.
- القياس الفعلي: زمن التقرير ≈ 0.06 ثانية، وزمن الاستعلامات 0.001–0.06 ثانية.
- التنظيف التلقائي: مهمة يومية تحذف السجلات الأقدم من "مدة الاحتفاظ".
  مهم: value = 0 تعني عدم الحذف التلقائي إطلاقاً (الوضع الافتراضي الآمن).
- السجلات الأصلية في Frappe (Route History / Activity Log / Access Log) تديرها
  إعدادات Frappe.Log Settings (90 يوماً افتراضياً) وهي لم تُعدَّل.

12) استكشاف الأخطاء الشائعة
================================================================================
- التقرير لا يظهر في القائمة:
    نفّذ migrate ثم clear-cache، وتأكد أن التقرير "standard" ضمن module "custom app".
- التقرير لا يعمل لدور "مدير الرقابة":
    تأكد من إضافة الدور للمستخدم؛ وتأكد أن المستخدم ليس لديه صلاحية أقل.
- الواجهة بالعربية جزئياً:
    نصوص CSV مُخزَّنة مؤقتاً في Redis؛ نفّذ clear-cache بعد أي تعديل على
    translations/ar.csv. وتأكد أن الترجمة ليست معرَّفة في تطبيق آخر بمفتاح
    ونص مختلف (مثال: "Source" كانت تُترجم "Target" في hr_erp؛ استُخدم
    "Event Source" لتفادي التعارض).
- لا تُسجَّل أحداث المستندات:
    تأكد من تفعيل "تسجيل أحداث المستندات" وأن نوع المستند غير مستثنى.
- ازدواج الأحداث:
    راجع "نافذة منع تكرار تسجيل المسار" و"مدة الاحتفاظ" في الإعدادات.
- لا تظهر زيارات الصفحات:
    المتصفحات قد تمنع ترويسة Referer؛ يعتمد النظام على Route History كبديل.

13) حدود النظام (ما يمكن وما لا يمكن رصده)
================================================================================
1) تصفّح الواجهات: يُرصد من ترويسة Referer (يعكس تفضيل المتصفح) أو من
   Route History الأصلي. يمكن تزوير Referer برمجياً من سطر الأوامر، لذلك
   لا يُعدّ دليلاً قاطعاً وحده. أما هوية المستخدم والمنفذ فمن الجلسة
   الموثّقة على الخادم فهو موثوق.
2) تنزيل الملفات: يُرصد مسار الطلب ونوع العملية فقط، دون اسم الملف أو
   محتواه أو وقت النقل.
3) محاولات الدخول الفاشلة: نعتمد على آلية Frappe الأصلية (Activity Log) +
   مرآة after_request. لا يتم تعديل ملفات المصادقة الأساسية.
4) سجل Version لا يحتوي اسم المستخدم، لذا تُنسب تغييرات الحقول إلى "Frappe"
   دون مستخدم ما لم يُسجَّل الحدث في سجلنا الموحّد.
5) printview يُسجَّل في Access Log الأصلي (من الخادم) بينما تنزيل PDF الفعلي
   عبر download_pdf يُرصد في سجلنا؛ قد يظهر حدث واحد لكل منهما لنفس الطباعة.
6) التعديلات داخل جداول فرعية (Child Tables) لا تُقارن حقلاً بحقل في
   التقرير (تُسجَّل أسماء الحقول الرئيسية فقط).
7) لا يمكن رصد: تعديل قاعدة البيانات مباشرة، تنفيذ SQL خارج التطبيق، أو
   الطباعة من خارج المتصفح (Print System).
8) المؤشرات إحصاءات نشاط، وليست دليلاً على إساءة الاستخدام.
